# Channel: Working document (always on)

Maintain a **living working-state document** throughout every brainstorm — even a quick, ephemeral-feeling one.
It is the brainstorm's **durable home**, and it does two jobs:

1. **Anti-drift within a session:** over a long back-and-forth, decisions confirmed early get lost, altered, or
   watered down if the only artifact is built at the very end. Capture each confirmed point *as it locks*.
2. **Survival across degradation:** context decays over many turns, and compaction or a new session can drop
   what was decided. A written, continuously-updated doc is where the brainstorm *persists* so it can be picked
   up intact — within this session, after a compaction, or in a future one.

## Rules

- **It is the agent's memory + the durable record — NOT a polished deliverable the user reviews.** Do not
  confuse it with user-facing artifacts (mockups, final specs), which follow fidelity-tracks-phase. This one
  runs at working fidelity the whole time.
- **Append/refine as decisions lock.** When the user confirms a point (explicitly, or by silence = approval),
  write it down immediately so it can't drift on a later turn.
- Keep it structured enough to be scannable — confirmed decisions, open questions, discarded options (with the
  reason they were killed, so they don't get re-proposed).
- Write it somewhere durable and appropriate to the topic (e.g. a design-record markdown file for a build; a
  scratch note for a lighter session). It is fine — encouraged — to create this early; it is not the
  "premature polished artifact" the anchoring rule warns against.
- At the exit, the working doc is what feeds capture / handoff / plan / build — the confirmed state is already
  captured, not reconstructed from memory at the end.
