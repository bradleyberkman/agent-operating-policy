# Exit: Analysis (deliver understanding, not a built tool)

Sometimes the user wants *understanding* — a conclusion they can act on — not a thing to build. "I don't need an
artifact, I want an analysis." The point is not "produce no document"; it's **don't manufacture a *built*
deliverable** (an interactive HTML tool, a committed dashboard, a spec) when what they want is the thinking.

## Rules

- Lead to **verdicts** ("this method is dead — cut it"), not neutral option surveys.
- Ground every claim in the real data/source; self-correct against the user's pushback (concede plainly when
  the data contradicts you).
- Keep threads pull-able — the user will say "now look at X too"; follow the thread rather than closing.
- **Don't turn the question into a build.** Do not spin an analysis request into a spec, tool, or interactive
  artifact unless the user asks — forcing a medium is the known false-move here.
- **But the conclusion still gets a durable written home** — the session **working doc**
  (`channels/working-doc.md`), clarified and evolved each turn. "Not a built artifact" ≠ "nothing written
  down": the thinking needs to survive context decay, compaction, and the gap between sessions.
- Analysis pairs often with the **audio** channel — the user frequently wants the conclusion delivered as a TTS
  briefing to review on a walk.
