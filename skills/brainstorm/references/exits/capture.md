# Exit: Capture (route to the right durable home)

When the brainstorm surfaces something worth keeping — work to do later, a decision, a learning — capture it in
the *appropriate* place and stop. This is a first-class outcome, not a failure to converge.

## Where it goes — pick by what it is

Route to the destination that fits, and let that destination's own skill own the format — don't re-specify it here:

- **A task / future work** → the project tracker via its own workflow skill. If it doesn't pass the definition of ready,
  surface it in chat to scope rather than filing noise.
- **A durable learning / correction / fact about the system** → the project's knowledge base via its own skill.
- **A durable fact about how the user works, or a project's state** → agent memory.
- Often the right home is simply the session's **working doc** (`channels/working-doc.md`) — not everything
  needs to leave the conversation.

Pick one deliberately; don't default to a tracker issue for things that aren't tasks.

## The one hard rule — no biased handoff plans

For anything captured as a **handoff to a future or fresh context**, record the *facts of the circumstance +
the open question + links* — and do NOT prescribe first steps or a recommended approach. Accumulated-context
analysis carries bias; the plan should be formed fresh by whoever picks it up.

This rule is scoped to *biased handoffs*, not all capture. A conclusion or plan genuinely **co-derived with the
user in-session** is fine to record in full (see `plan.md`) — the anti-pattern is specifically the agent
*unilaterally* prescribing next steps at handoff.
