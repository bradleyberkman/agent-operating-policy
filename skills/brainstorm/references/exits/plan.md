# Exit: Co-derived plan

A plan is a legitimate output **when it was built together in the live session** — the user shaped it,
challenged it, and signed off on the pieces. The anti-pattern is a plan the agent prescribes *unilaterally*
(especially at end-of-context handoff), which the user explicitly distrusts as biased.

## Rules

- Only produce a plan whose steps were actually surfaced, challenged, and accepted *with* the user (silence on
  a step = approval, per the interaction rules — but the step still had to be put in front of them).
- Keep it a living thing: as the user gives feedback, update the working doc (see
  `channels/working-doc.md`) so confirmed pieces don't drift or get watered down over a long exchange.
- When the plan is genuinely ready to execute, hand off to the execution machinery (a planning or
  execution skill) rather than executing inline — the brainstorm's job was the thinking.
- If in doubt whether the plan is co-derived or agent-imposed, route to **capture** (facts + open question)
  instead.
