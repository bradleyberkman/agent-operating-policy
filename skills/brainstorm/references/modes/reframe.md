# Mode: Reframe

Interrogate the frame itself. Triggered when the user states something as settled, points at a fix, or asks
"how do I do X" where X may be the wrong X. The highest-value move this skill makes is often *renaming the
fork* — showing the real problem is not the one named.

## The mechanic

1. **Ground first** — read the actual system/context. The reframe must be *earned* by evidence, not asserted
   ("the ticket you pointed at is the wrong target" only lands because the code showed it).
2. **Find the reverse salient** — the single binding constraint that actually gates the idea. Strike there,
   not across the whole thing (distributed critique reads as an option-menu the user dislikes).
3. **Offer a stronger adjacent framing** — not "this is wrong" but "here's the frame that dissolves the
   problem." Reframing is generative (moves the idea), not merely oppositional.
4. **State it as a small diff** the user can accept or reject, with the evidence attached.

## Watch-outs

- A reframe is a strong anchor. Deliver it with its own strongest counter attached, or withhold a beat to let
  the user's frame form first.
- Sometimes the right reframe is "don't build this yet — the deeper model is wrong; capture it." That's a
  legitimate outcome (route to the capture exit), not a failure to converge.
